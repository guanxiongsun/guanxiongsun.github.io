STPN

Spatio-temporal Prompting Network for Robust Video Feature Extraction

Guanxiong Sun, Chi Wang, Zhaoyu Zhang, Jiankang Deng, Stefanos Zafeiriou, Yang Hua

In one paragraph

Deteriorated frames (motion blur, defocus, occlusion) hurt every video task. Prior work compensates with heavy integration modules, a different one per task. STPN instead predicts a few video prompts from neighbouring frames and prepends them to the current frame’s patch embeddings, so a standard backbone, with no task-specific module, produces robust features for detection (ImageNet VID), instance segmentation (YouTube-VIS) and tracking (GOT-10k).

The problem

Video frames rarely stay clean. The object moves fast and blurs, the camera loses focus, something passes in front, or the animal turns into an unusual pose. A network that looks at one frame at a time loses exactly the evidence it needs, and the fox in Fig. 1 is a typical case: sharp in a neighbouring frame, a smear in the current one.

The usual remedy is to borrow from neighbouring frames. Methods such as SELSA, MEGA and TransVOD run every frame through the backbone and then fuse the features in an attention-based integration module. That works, but the modules are heavy and complex, and each one is built for one task: a module designed for detection does not carry over to instance segmentation or tracking (Fig. 1a).1

1 The paper evaluates three tasks: video object detection (VOD, on ImageNet VID), video instance segmentation (VIS, on YouTube-VIS) and visual object tracking (VOT, on GOT-10k).

STPN asks a different question. Instead of repairing features after the backbone, can we change what goes into it, so that one standard backbone produces robust features for every video task?

The idea

Fig. 2 rebuilds the pipeline with real pixels from the paper’s figure: a sharp support frame and the motion-blurred current frame. The frame is cut into patch tokens, and STPN puts five prompt tokens in front of them. Pick any patch to see what it can read inside the backbone, then switch to the prior pipeline and change the task.

In words: the prior pipeline sends 40 patch tokens of the blurred current frame through the backbone and fuses the support frames afterwards, in an integration module built for one task. STPN predicts 5 prompt tokens from the support frames and prepends them, so 45 tokens enter a standard backbone with no new layers and every patch can read the prompts. Each task keeps its own framework and head, with no integration module.

How to read this

The frames are real crops from the paper’s Fig. 1; the grid size and attention lines are illustrative, not measured attention (in Swin-T a patch attends to every patch in its 7×7 window; three neighbours are drawn). The VOD / VIS / VOT switch is illustrative too: the released configuration is the VOD detector (Faster R-CNN, Swin-T), and segmentation and tracking are separately trained models in their own frameworks (see the paper). What matches the released configuration: 5 prompts of 96 dimensions, predicted by 5 learned queries attending over the support frames’ last-stage features, prepended to the patch embeddings at the backbone input only (num_tokens=5, location='prepend', deep=False), and computed once per video from 14 reference frames spread over it. At the test resolution (up to 1000×600), Swin-T’s 4×4 patch embedding produces up to 37,500 patch tokens; STPN adds just 5.

How it works

Panel (b) of the paper’s figure has five parts. Select a number to highlight its note.

At test time, the released model samples 14 reference frames spread evenly over the whole video and passes them through the backbone without prompts. The DVP predictor takes their last-stage features (768 channels in Swin-T) and projects them to 96 dimensions, the width of Swin-T’s patch embeddings. Five learned queries then attend over every spatial position of those features, and each query becomes one prompt token.

The prompts are prepended to the current frame’s patch embeddings and travel through all four Swin stages. In every shifted-window attention layer, each 7×7 window attends to the same five prompts, so any patch can read a summary of the video; when patches merge between stages, the prompts are carried along. Before the feature pyramid the prompts are dropped again, so the neck and the task heads are the unchanged still-image ones.

Two things follow. The predictor is small, about 0.11 M parameters,2 and the released code computes the prompts once per video, at its first frame, and reuses them for every later frame, so each further frame costs only five extra tokens. And because nothing after the backbone changes, the same design carries over to segmentation and tracking frameworks without a new integration module.

2 111,552 parameters, counted from the released predictor in vfe/models/vid/stpn.py: a 768→96 projection, 5 query vectors and four 96×96 linear layers.

Key idea

Don’t repair features after the backbone. Tell the backbone about the video, with five tokens at its input.

Where it led

  1. 2021MAMBAa memory bank that enhances features after the backbone
  2. 2023STPNvideo context as a few tokens at the backbone’s input
  3. DirectionPhysical AImemory for agents that act

MAMBA kept a memory of features and read from it after the backbone; STPN compressed a video’s context into five tokens that the backbone reads at its input. My current direction, Physical AI, takes the same question, what to remember and where to feed it in, to agents that act in the physical world.

Open question

Can a VLA take its memory as a handful of prompt tokens, the way STPN’s backbone takes its neighbours?

Code

STPN is maintained in vfe.pytorch, a plain-PyTorch rewrite that also holds MAMBA; the original ICCV code is at guanxiongsun/STPN. To evaluate the released checkpoint (CHECKPOINT is the stpn_swint_adam_9x model; data setup is in the README):

uv venv --python 3.12 && uv sync
python -m vfe.cli.test configs/vid/stpn/stpn_swint_adam_9x.py \
    CHECKPOINT --work-dir WORK_DIR
